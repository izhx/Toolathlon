# 大规模 agent 数据合成环境设计

日期：2026-09-10。本文均为设计 D；规模/费用数字为规划假设 A，尚未部署、压测或生成训练数据。各服务事实见 [shared.md](shared.md) 和 [服务报告](services/)；阶段边界是设计而非实施。

## 1. 职责和数据边界

环境模拟器负责工具契约和业务状态；初始环境生成器负责造出合法、多样且有背景的资源；任务生成器负责把状态中的业务需求表达成用户任务；独立评测器负责验收结果。四者版本分别记录。模拟器和仿真 LLM 不接收 groundtruth、隐藏评分约束、参考答案、最优调用轨迹，也不根据任务完成度改变 API 返回。

生成器可以知道私有任务约束以验证可解性，但输出给环境的仅是合法业务资源。任务正文可明确给出用户授权和成功标准；隐藏评测器中的 ID 集合、SQL 答案、未来事件以及参考路径不能写进 agent 的工具描述、资源命名、异常提示或仿真 prompt。环境文本始终是业务数据，不得改写仿真规则。

业务后端优先本地/自控。公网依赖按五类分别计量：agent 模型 API、仿真模型 API、依赖/镜像下载、外部业务 API、业务内容 URL。缓存安装包不等于业务可离线；内网模型可使模型链也不依赖公网，但成本仍应计 GPU/服务资源。任意代码、SQL 外部函数和文件 URL 的出口属于显式 profile；不可静默落到真实账户。

## 2. 生成多样且一致的初始状态

每个环境 manifest 记录 `generator_version, schema_version, semantic_profile, seed, clock_origin, principal_set, distribution_config, content_bundle_hash, state_hash`。seed 派生为独立随机流：ID、结构、内容、权限、历史、故障/时延，增加某类采样不应扰动其他流。ID 形状和 URL 按服务规则生成；seed 与答案不可编码到可见名称中。

| 轴 | 建议采样和约束 | 防止的低质量规律 |
|---|---|---|
| 资源规模 | 小/中/大分层；每类至少覆盖 0、1、分页边界前后、多个页、超长内容；具体上限按服务限制 | 永远一页、空集永远是错误、没有检索必要 |
| 结构 | 多项目/文件夹/分支/工作表/页面层级，稀疏和密集关联；ACL 不一致、归档、孤立但合法对象 | 把服务视为扁平 JSON 列表 |
| 命名和内容 | 多语言、常见/罕见词、相似名、重名、改名历史、内容近重复、领域长尾；多种独立内容生成来源 | 根据前缀、模板位置或内容风格直接猜答案 |
| 类型与缺失 | 缺字段/null/空串/空集合/零/false 分开；时区/DST、精度、枚举、Unicode 和二进制长度按契约 | 缺失当零、字符串和数值混用、时间排序错误 |
| 历史与时间 | 先生成合法事件序列再物化当前态，包含失败/撤销/重试/延迟索引；读缓存有版本 | 当前状态与历史矛盾、无生命周期 |
| 权限与干扰 | 可访问目标 + 相似但非目标资源 + 不可访问对象；不可访问对象不得从搜索泄漏 | 默认全权、无权限时自动建资源 |
| 业务关系 | Drive file 与表单/表格、Git ref 与 commit、run/artifact、表外键或业务约束显式连接 | 各 API fixture 自说自话 |

初始化采用两阶段生成：LLM 可先生成组织背景、文本、表单问题、报告/issue/卡片等内容提案；确定性构建器分配 ID、建立关系、类型化数值、ACL、版本和时间线。所有业务约束检查通过后一次提交快照。LLM 自述“有效”不能替代校验。长文档/附件提前生成，以内容摘要定位；任何截断或摘要都不得成为原文的权威替身。

数据分布不是一份固定 fixture 的随机改名。每个 seed 输出分布统计：实体度数、层级深度、分页次数、长度分位数、重复率、时间跨度、权限拒绝比例、null 比例、语言分布。以多来源真实记录中可获得的脱敏统计为目标；尚无记录的分布标假设，不声称拟合真实流量。

## 3. 两条任务生成路线与可解证明

**从状态产生任务**：在已验证环境中选取业务谓词，生成需要查询、判断、更新或产物创建的请求。保存私有目标谓词与允许变更范围；自动求解器只用来证明存在可行路径，参考路径不提供给模拟器。随机改变入口、资源名、无关对象和工具顺序后，结果目标应不变。

**从任务约束构建状态**：约束求解器分配资源与权限，构造满足前提的环境，再加入不改变目标可解性的干扰项；独立可达性检查避免目标权限永远不可获得、查询无解、外部执行不受支持。对真正不可完成任务，任务标签与评测目标应是正确识别阻碍并报告，不能假装成功任务混入可解集。

目标以状态/业务结果表达，例如“所需候选事件均在时间窗内且无冲突”“指定业务记录变更而其他记录不变”“合并结果满足内容与祖先约束”；不用“必须第 3 步调用工具 X”。同时验证安全/授权范围和负面不变量，避免把多删数据的投机路径判为通过。

任务集合按操作图采样：链、分叉、合流、重复读取、失败恢复、异步轮询、分页后批改、跨入口交叉读写、跨服务复制/引用。保留工具族、图结构和业务领域的独立 holdout；在训练未见结构中重新组合已知合法操作，另设新 schema/profile 的版本迁移集。finalpool 仅是一个独立回归集，不定义覆盖上限。

## 4. 独立验证与 oracle 防同源错误

评测器读取只读状态导出/审计事件/独立执行结果，不依赖工具的 `success`、agent 总结或仿真 LLM 判断。不得直接导入模拟器的业务处理函数作为唯一 oracle。建议由不同作者写最小关系/约束检查器；SQL 用人工审定小表期望值 + 官方样例 + 受控真实查询记录，不能让同一转译器既执行又算期望值。

所有任务保存可读目标谓词、观察入口和 oracle 独立性说明。通过 mutation testing 注入“写操作无效却成功、删错引用、分页重复、忽略 ACL、NULL 当 0、漏写版本、幻觉 ID”等错误，要求 oracle 拒绝。文本质量可另用独立模型/人审评分，但结构事实、数值和执行正确性不交给模型裁决。

差分比较采用资源双射映射与关系保持，不能把所有 ID/时间字段删除：父子引用、URL/ID 对应、版本增长、时间单调性仍须验证。只对不影响业务的随机 ID 或服务时钟做语义归一；当时间本身是目标，比较时区/瞬时点或服务日期语义，不能宽容漂移。

## 5. episode 隔离、事务和恢复

建议 metadata/事务存储使用自控 PostgreSQL 的独立服务域表（或原型每 episode SQLite）；文件和 Git 对象使用内容寻址 blob/本地仓库。PostgreSQL 仅承担存储与事务，不是 BigQuery/Snowflake 兼容层。当前官方 PostgreSQL 18 文档说明可串行化事务可能失败并需整事务重试；RLS 的 owner/superuser/BYPASSRLS 有绕过条件，所以不能仅靠加 episode_id 就宣称隔离。[事务隔离](https://www.postgresql.org/docs/18/transaction-iso.html)、[行安全](https://www.postgresql.org/docs/18/ddl-rowsecurity.html)（版本 18，查阅 2026-09-10）。

| 机制 | 设计决策 | 必须覆盖的失败点 |
|---|---|---|
| episode 边界 | 网关从独立会话/凭据映射 episode；模型不能通过参数自选其他 episode；每键含服务域和 episode，FK/索引/缓存/blob ACL 同样隔离 | SDK 未绑定会话、缓存漏 namespace、管理连接绕过策略 |
| 更新并发 | 读取版本/read-set，写入事务检查；按真实服务决定冲突、last-write-wins 或整批拒绝，不能全局统一一种语义 | 丢更新、重复创建、同名不同 ID、真实非原子操作被变成原子 |
| 幂等与重试 | 记录调用 ID 和提交收据，用于恢复诊断；只有真实接口承诺幂等时才按幂等键去重 | 对非幂等 create 自动去重会训练错误重试规律 |
| 异步任务 | 独立状态机及可控事件队列，submitted/running/succeeded/failed/cancelled 按服务定义；有执行产物才能成功 | 轮询凭次数成功、重置后旧 job 写入新 episode |
| 快照/克隆 | 基线快照 + episode overlay + 事件日志；blob 可共享不可变字节，访问关系不可共享权限 | 只复制表数据却漏索引/附件/ref/虚拟时钟 |
| 崩溃恢复 | 提交前崩溃无变更；提交后响应丢失可查收据重放原响应；恢复同时重建队列和搜索索引水位 | 双提交、缓存旧态、对失败请求重启业务写入 |
| reset | 将旧 episode 封存，创建新 generation；旧会话/job/cursor 失效，既有日志保留 | 共享全局清理、ID 重用造成串读 |
| 记录与回放 | 保留原调用、归一化调用、权限上下文、读版本、虚拟时钟推进、输出、状态 diff、排序决定、profile/软件版本 | 只有 seed 或 temperature=0 不能复现服务和模型行为 |

大规模优先共享服务进程、多租户隔离和不可变内容；需要执行不可信代码/Git hooks 等的服务使用 episode 沙箱，并单列 CPU/内存/网络成本。控制进程、任务容器、模拟服务与 Docker daemon 是不同边界。不得复用现有全局 deploy/reset 来回收 episode；本阶段也没有执行该脚本。

这里的共享进程优先指经过隔离检查的业务后端。带全局 SDK 身份/active run/缓存的 MCP wrapper（例如 W&B）按固定 episode/主体隔离进程或验证过的固定会话，不能为减少进程数而并发替换全局认证配置。将 wrapper 启动成本与后台共享存储成本分开压测。

## 6. LLM 状态提案架构

```mermaid
flowchart LR
  A[工具调用与会话] --> B[契约校验与身份权限]
  B --> C[查询相关状态及版本]
  C --> D{能力路由}
  D --> E[确定性执行]
  D --> F[LLM 结构化提案]
  F --> G[独立契约与业务校验]
  G --> H[版本检查及原子提交]
  E --> H
  H --> I[从提交态渲染返回]
  I --> J[调用记录与可验证回放]
```

“LLM 主导”不是每次调用重写世界。它在选定能力内负责解析/组合复杂内容或提出状态变更；确定性外壳仍负责身份、schema、引用、时间/数值、执行、持久化和可见输出。仿真模型不等同于本次分析 agent 的模型选择。候选模型按盲测质量与有效轨迹总成本决定。

入口校验应重现固定 handler 的参数投影/默认/拒绝规则，另外记录其与广告 schema 的差异；不能统一加强校验后宣称接口未变。原始 MCP 已知有误导性成功文本时，兼容回归可重现有证据的包装，但独立状态评测不得判业务成功，此类记录默认隔离出主训练集；未实现能力不能借这个例外伪造成功。

状态检索由工具参数和权限制定查询计划：直接 ID 先查对象及父级 ACL/必要引用；搜索先确定查询候选全集/索引快照，再排序分页；修改包含受影响后代/引用和版本。缺数据可以继续检索，超过预算返回明确的受限能力错误或走真实执行组件，不能因上下文窗口装不下就遗漏资源。摘要携带来源 ID/版本/摘要 hash，可用于定位，校验时仍取完整状态。

LLM 输出限于预定义的命令/patch 集与字段来源（已存在字段引用、新生成内容、派生字段）；拒绝越权 patch、悬空引用、无依据的读字段和凭空执行结果。LLM 不能把非法参数改为合法参数代替 agent 修正。对无效提案最多内部修复 1 次（A，可调）；修复只接校验错误及原始合法上下文，不提供“怎样让任务成功”。仍失败则不提交，并按 profile 返回公开的仿真失败。不要假冒真实服务本应成功的业务错误；这类基础设施失败单独标注、轨迹隔离。

提交时 read-set 版本不匹配则放弃过期提案，重取状态后按真实并发语义重试或报冲突。最终输出从提交态生成；若需要自然语言，模板填入结构化事实或校验每个事实来源，不能在提交之后让 LLM 再生成不受控新事实。对于真实非原子接口，将其合法部分提交边界显式建模，不能以本架构原子性抹掉真实部分成功行为。

只读缓存键至少包含服务/profile、主体及权限版本、参数、相关状态版本、虚拟时间窗口、模型/prompt 版本；读取未提交 proposal 不能填缓存。相同快照回放读取已有结果，不能再次采样 LLM。永久回放记录包括模型供应商/版本、prompt 版本、原始输入状态、模型输出、校验意见、重试次数、最终提交/响应 hash；凭据脱敏，权限语义以模拟 principal 表示。

## 7. 成本和吞吐模型（A）

总成本采用 `开发+维护+初始化+每次调用+验证+失败废弃/重跑+存储/执行`，比较的是**每条通过独立验收的轨迹成本**。纯代码单调用不额外用模型；内容预生成的混合路线把 LLM 成本摊到多次使用同一环境的合法任务，但任务切分需防止训练/测试共用内容。

令 N 为工具调用数、f 为进入 LLM 的比例、r 为平均额外修复调用数、a 为每次仿真需模型数、Tin/Tout 为每次模型 token，pin/pout 为每百万 token 单价，则仿真模型费为 `N*f*a*(1+r)*(Tin*pin+Tout*pout)/1e6`。另加生成/评测模型费用；f、r、上下文长度必须实测分布，不能只报均值。

规划例：N=1,000,000，Tin=8,000，Tout=1,000，a=1，r=0.1，假设 pin=$2、pout=$8（**敏感性用虚构价格，不是任何供应商报价**）。每次 LLM 主导工具调用 $0.0264，100 万次约 $26,400；f=0.05 的混合路线约 $1,320；纯代码仿真模型费为 0，但有开发/CPU/数据库费。价格或上下文翻倍近似相应翻倍；如果对一个调用进行 LLM 执行+LLM 验证，还需显式增加 a，且同模型自评不构成独立正确性。

假设每模型调用总延迟 3 s（规划 A，非测量），100 tool/s 在 f=1、r=0.1 下约需 330 个模型在途请求；f=0.05 时约 16.5 个，均不含队列/尾延迟。100 tool/s × 8,000 token × 1.1 = 880,000 input token/s 是全 LLM 示例的输入配额量级；这比仅看请求并发更容易成为瓶颈。每调用完整状态 100 KiB 的 100 万记录约 100 GB，8,000 token 输入/完整 blob 另计，说明需快照+diff+内容去重但保留可重建性。

开发成本不在未做试点前报精确人日承诺。用按能力记录工时的方法比较：接口提取、状态规则、后端适配、差分样例、LLM prompt/validator、上线维护各自记账。LLM 主导可减少长尾响应/内容规则代码，却不能省掉 ID/ACL/计算/并发/检验；复杂 SQL/执行场景还可能增加双重系统成本。两路线 break-even 调用量为 `(代码固定成本-混合固定成本)/(混合每有效调用成本-代码每有效调用成本)`，分母≤0 时不使用该阈值推断。

降本顺序：提前生成内容 → 确定性读取/分页/数值快速路径 → 以正确性门槛选择能力对应模型 → 安全版本缓存 → 离线批处理 → 将高频稳定能力固化为代码。批处理只用于相互独立 episode 或合法独立读，不能打乱同资源因果关系。尾延迟超预算先降并发/分流，不通过删校验来提速。

## 8. 质量监控与发布策略

发布前按 [validation-plan.md](validation-plan.md) 分层验收；缺陷保留原始运行记录但隔离出训练集。每条轨迹附 capability/profile、生成器版本、oracle 版本、仿真比例、故障类型、支持边界、质量标签。能力覆盖分母必须是对应完整工具快照以及 profile 的合法语义集合，不仅是“成功调用过”。

监控硬指标：非法接受率、幻觉实体/字段率、读写不一致率、越权泄漏率、结果与提交不一致率、跨 episode 污染率、恢复双提交率、回放 hash 不一致率。软指标：文本多样性、重复模板/命名预测答案的准确率、错误恢复分布、工具选择与真实记录分布差异、长交互漂移增长、p50/p95/p99 与有效轨迹成本。不要把高任务完成率当高保真；“总是成功”的假环境恰好可能有最高完成率。

以能力版本发布：新功能经过契约、语义、组合、真实差分和新结构集后才进入 profile；旧 profile 保留可回放。固定 MCP 缺陷需要兼容样例，但默认不把利用缺陷的轨迹加入主迁移训练集。针对服务修正版另列版本，不静默修改同一 profile 的行为。
