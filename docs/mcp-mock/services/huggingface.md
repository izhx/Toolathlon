| Collection / Paper / Documentation | collection slug/owner/items 顺序/类型引用；paper ID、元数据、日期、链接、upvotes、关联 repo；文档产品/版本/路径/anchor、正文与索引。保留缺失/失效/访问受限引用，业务允许的外链不强制成为本地实体；不为回答任务自动补写论文事实。 |
| Jobs / Schedule / Sandbox / Process（选配） | 主体、image digest、literal argv 或 shell、env/secret 引用、volume、flavor、预算/timeout、排队运行终态、日志序列与输出 blob；schedule→多次 job；sandbox→job/挂载/进程/handle generation。真实执行产生退出码/文件，取消和超时保留部分产物；不能依“预计成功”推进终态。 |
| Space / ProxyToolProfile（选配） | Space repo/revision、build/runtime 状态、工具 schema hash、动态名、上游协议、文件 URL/队列/任务状态、模型版本。创建/上传 Space 不等于构建成功或可推理；provider 输出只由被选定真实组件或明确近似生成 profile 产生。 |

ID/URL 路由（D）：对 agent 保留合理的 Hub URL 与 `hf://` 格式；本地入口通过 episode 请求上下文与模拟身份路由，而非让 agent 猜 episode 前缀。`https://hf.co/...`、`https://huggingface.co/...`、`hf://models/...@revision/path`、Git remote、SDK repo_id 均映射同 repo type/ID/commit；外部 URL 保存来源/bytes/hash/ACL/过期关系。HF 的 `hf://` MCP URI 与 Python HfFileSystem 的版本语法分别按源解析，不强行用一个通用 path parser。

执行器内部可以记录排队、资源准备等事件，但不因此添加工具没有的公开 stage；S:`jobs/types.ts:44-50` 的 JobStage 是 RUNNING/COMPLETED/CANCELED/ERROR/DELETED，其他中间信息应按已核定输出字段投影。调度器真值、公开状态和文字日志分开保存，避免把本地运行器的状态枚举当成 HF 契约。

入口路由至少分五类：①本地 MCP wrapper/协议；②HfApi、Hub JS client 的 metadata/commit/tree/whoami 等 HTTP；③raw/resolve/HEAD/Range、LFS/Xet 和签名对象 URL；④Dataset Viewer `/splits /size /parquet /rows`；⑤Git/CLI/Python/Space/JOB 子进程及外部文件 URL。H:`constants.py:67`/DS:`config.py:21-22` 支持 HF_ENDPOINT，但 S:`repo-search.ts:133` 硬编码 Hub API、S:`dataset-viewer-inspect.ts:5,173-179` 用独立 Viewer client；S:`mcp-server.ts:469,522` 未注入自定义 hubUrl。任务 hardcoded raw URL 也不会随 HF_ENDPOINT 改。采用局部 client factory/HTTP 网关等适配属于未来设计，不能声称现有配置开关已足够。

下载契约引用 H:[file_download.py:1534-1584](https://github.com/huggingface/huggingface_hub/blob/v0.33.4/src/huggingface_hub/file_download.py#L1534)：commit hash、ETag、size、location/Xet 元数据参与缓存和下载，单纯返回 HTTP 200+bytes 仍可能让 SDK 失败。H:`hf_api.py:3682,3799,4305` 分别为 create/delete/commit endpoints；`4139-4145` 为 parent_commit 语义。下载 `revision` 可为 branch/tag/PR/full commit，CLI 复用下载 helper，见 [v0.33.4 下载文档](https://huggingface.co/docs/huggingface_hub/v0.33.4/en/guides/download)。

身份差异必须显式测试：private、gated、模型卡片可见与权重可下载不等价。gated grant 是 individual user，不应由组织成员身份自动继承，见 [官方 gated models](https://huggingface.co/docs/hub/models-gated)。401/403/404 是否隐藏资源存在依实际 endpoint/账号 profile 校准，不能所有入口都统一给“权限不足”。

## 4. 代表性交互序列

以下 D 均从状态图产生，操作可替代/交错；M 的具体步骤仅在对应已冻结工具可见时使用，SDK/Git 操作明确属 X。

| 序列 | 状态断言与要排除的伪保真 |
|---|---|
| 1. X/create 或选配 create_repo → X/upload 或 hf_fs_write → hf_fs cat → SDK snapshot → 删除后读取 | 同 repo type/commit 的文本/图片 bytes 相同；不存在后按真实错误；上传失败不能凭 success 预建文件。 |
| 2. search 多类型同名 → details 自动检测 → 指定 dataset → structure → preview 两页 | 返回类型消歧保留多个匹配；页边界不重不漏、offset 是行偏移；多 config/split 省略须提示选择，不能擅取第一个。 |
| 3. 先 SDK 提交 A → Git checkout A → ref 更新 B → hf_fs 指定 A cat → 默认分支读取 | A 不变、默认 ref 为 B，缓存按 commit/权限/version 隔离；不得所有 revision 返回最新文件。 |
| 4. 两客户端读取 parent P → X/M 提交 Q → 另一客户端用 P 写入 → 冲突后重读并修正 | 过期前置条件失败且不覆盖 Q；非法 SHA 不静默修复；PR 操作不误更新 main。 |
| 5. hf_fs 批量 cat 已知文本、attach 图片、cat 不存在、search 非法 scope | 按 input index 返回成功和错误，图片 MIME/hash 正确；混合批不因单项失败丢成功项，全部失败才按 wrapper 设 isError。 |
| 6. anonymous 搜索/读 card → 受限权重下载失败 → 换已授权主体 → SDK/HTTP/MCP 再读 | 可见性和 gated grant 生效，cache 不泄漏；仿真器不自动为主体授予权限。 |
| 7. 数据集 CSV/JSONL/shards → SDK load_dataset → Python 转 typed parquet → 上传新 dataset → Viewer 构建后检查 | 新 repo 有真实输出文件，row count/schema/order/null/media 来源一致；构建中不能立即编造完整 preview。 |
| 8. collection/paper/docs 发现 → 精确 paper.md/card cat → GitHub issue 或 Sheets 引用 | 来源 ID/URL/版本和被复制文本可追溯；不强制固定找资料顺序，不把评测答案送入 HF。 |
| 9. hf_fs_write put bucket → Sandbox 挂载读写 → hf_fs 读当前对象 → 再请求 branch/PR | bucket 当前 bytes 更新；不提供虚构历史；后者按不支持边界失败。仅 S-config 执行 profile。 |
| 10. Jobs 提交 → logs/inspect 交错 → 失败/取消/timeout → 检查部分文件；或 Space 查 schema→invoke→URL 作为下一输入 | 终态来自真实进程，logs 序列/退出码/产物对应；调度和取消不默认瞬时完成；未配置 execution 的 profile 显式失败，不假造推理结果。 |

`hub_repo_search` 没有 MCP cursor；序列 2 的行翻页用 details offset，仓库大列表翻页可用 SDK X。hf_fs 的截断按其能力处理，不能为满足测试擅加所有命令都支持 offset/cursor 的规则。

## 5. 候选实现与推荐

I/S/C/T/D/P 的判断均为可行性设计，未给运行得分。

| 路线 | I / S / C / T / D / P 与成本、适用边界 |
|---|---|
| 保留固定官方 MCP，替换 HTTP 后端（首选） | I 最接近原始说明/schema/formatter/错误分支；S/C/T 取决于同一 Hub 后端；D 来自 seed 内容；P 主要是文件/索引。需为 Hub/Viewer/对象/Space 多 client 注入路由，开发中高、运行低至中、上游升级需契约 diff。固定源码能替换并不证明托管部署完全相同。 |
| 有状态 MCP 替代实现（备选） | 适合无法稳定注入 wrapper 的分支；按匿名完整 JSON 和账号 snapshot 生成协议适配，但 description/error/text 必须逐项匹配；共享后端可使 S/C/T 接近首选，I 维护负担更高。不能只硬编码现有 5 任务。 |
| 本地 Hub HTTP/API + 真 SDK/CLI | 优先支撑 X，S/C 强；需要 metadata/tree/commit、HEAD/resolve/Range、错误/缓存、LFS 及 Viewer；不会自动获得 MCP I。单个 endpoint fake response 的低成本假象会转化为大量 SDK 兼容缺陷。 |
| 仅 SDK/client 适配 | 开发较低且易做 scoped profile，但硬编码 HTTP、Git、任意 subprocess 会绕过；修改真实 SDK 的字段/类型/默认会损伤迁移。只能是兼容边界的桥梁，不能作为“全部入口已模拟”的依据。 |
| Git + Git HTTP backend + blob/LFS 组件 | 官方 [git-http-backend](https://git-scm.com/docs/git-http-backend) 支持 Git fetch/push 协议，并不提供 Hub repo metadata/ACL/gated/Viewer。可复用 Git 对象/refs/历史，Hub HTTP commit 应真正写入同一对象图；读写权限在外层校准，不能直接沿用 Git HTTP 默认公开/认证行为。 |
| Git LFS 协议/本地缓存 | [Git LFS v3.7.0 batch 规范](https://github.com/git-lfs/git-lfs/blob/v3.7.0/docs/api/batch.md) 定义 upload/download、oid/size、逐对象 actions/error 和 URL 过期；可为基础存储提供实现依据，不能当现成完整 Hub。HF cache 仅版本缓存，离线开关不创建身份/搜索/写事务。Xet 是另一个传输/重建协议，LFS 实现不代表 Xet 兼容。 |
| 真 datasets/Python/Arrow + 受限 Viewer 适配 | 文件转换与 typed 行由真库执行，C 和数值保真较好；Viewer config/split/派生状态还要实现。DS 4.0.0 `load.py:915-917,989` 已拒 dataset scripts，不能为旧远程脚本开宽松后门。文件读取不等于完整 Viewer 平台。 |
| 本地容器、Space/推理组件 | 可提供真程序执行和有限模型推理；不自动实现 HF Jobs 的调度/权限/配额/日志契约或任意社区 Space schema。按 image/model/tool hash 冻结小范围，P 成本最高的一类；本阶段未运行。 |
| fixture/回放 | 用于精确协议 golden、只读差分与异常样例；I 在固定样例上高，S/C/D 对新顺序/写入弱。按状态/版本录制的 replay 可辅助，不按任务/调用次序直接返回答案。 |
| LLM 主导 | 可较快扩展卡片/自然语言长尾，但 I/S/C/T 仍需确定性底座，在线 tokens/延迟高；读文件、类型、ACL、计算和执行不能靠生成。若为每次读写重推状态，长期漂移及校验开发成本高。 |
| 混合（内容预生成优先） | 代码负责契约、权限、图、文件、索引/分页/执行；LLM 生成多样初态，少量语义搜索可在冻结候选上重排。I/S/C/T 由同一底座保住；D 可改善，P 在线成本较可控。需独立验证实际收益，不能先验称比代码更高保真。 |

本次没有核实一个能够直接替代完整 Hub 的现成自托管模拟器；因此不推荐仅凭“模型仓库/registry/缓存/推理服务器”名称作替代。推荐共享内容寻址存储、事件日志、episode namespace；HF 的 repo type、card/Viewer、gated、bucket/Jobs 规则独立。GitHub 与 HF 可共用 Git 对象处理机制，但不能共用未经映射的 issue/PR 编号、权限或 API 业务逻辑。

## 7. LLM 仿真可行性

建议 **代码为业务底座、LLM 生成初始内容的混合路线**。适合：在初始化生成相互关联的模型/数据集卡片、论文摘要、讨论文本、自然语言 dataset 示例、同义搜索查询与合理干扰项；这些都要合法地写入初态，拥有 ID/版本/来源。可实验：只在当前真实可见候选内，对文档/Space 的语义检索结果重排并生成服务本来会给出的摘要。HF read/cat 不属于“可生成新内容”的服务操作，不能因为文件长就让 LLM续写。

不适合由 LLM 决定：已有文件 bytes、commit SHA、版本图、ACL/gated、分页/排序数值、下载 hash/size/Range、parquet/Arrow 类型/row count、SDK 异常、进程退出/日志、模型推理精确输出、Jobs 成功/配额扣除。创建卡片时 agent 指定文本必须原样存储；仿真器不能顺手纠正 license 或补答案。Sandbox 的 exec 要真执行，不能用 LLM 预测 Python 输出。

三路线对照：纯代码需要更多内容模板与语义搜索工程，但每次工具调用无额外模型费；LLM 主导可较快写自然语言行为，却仍需 schema/权限/commit/typed/执行校验，可能形成两套难维护系统；混合把内容成本前移，只对有证据的长尾语义路径调用模型。开发成本用接口、后端规则、数据生成、validator、真实差分、维护工时分别记录，不在没有试点时承诺人日。

在线候选链路 D：tool call → 固定 profile parser/鉴权 → 查询权威状态及所有必要索引/文件引用 → LLM 提出受限摘要/候选排列或允许的状态提案 → 独立 schema、来源、ACL、版本及不变量校验 → 在真实服务提交单元内提交 → 从提交态渲染响应。相关状态包括 repo type/ID/ref、caller scope、visible 候选全集或完整检索页、index/source 版本、byte references；空结果必须来自实际索引查询。大文件只供已检索片段和 content hash，不把摘要当真值；上下文不足时继续检索或明确失败，不能假设未读取状态为空。

读操作禁止新增对象/字段；LLM 重排只能返回已有 candidate ID 的受限排列，输出里的标题/URL/metadata 从状态渲染，不从自由生成文本取值。写提案只包含明确 schema 的已授权 mutation，read-set 版本冲突则丢弃并按真实语义重读/失败；预上传和 commit 是不同边界，Jobs 提交与运行产物也不同。内部校验修复最多 1 次（A，可调），失败不提交，并标记仿真基础设施失败，不能伪装成用户本来合法操作的真实业务拒绝。

LLM 不接任务答案、目标选中 repo、评分字段或成功轨迹；资源正文作为业务数据，不能改系统规则。写后响应由提交态生成；检查 every ID/URL/field provenance、完全一致重复读、无授权更改、无“替 agent 修参数/补资源”行为。验证器来自独立规则/真实样例/盲审，不能由同一个仿真 LLM 自评。

规模成本 A：沿用公共模型 `N*f*a*(1+r)*(Tin*pin+Tout*pout)/1e6`，N=调用数、f=在线仿真比例、a=每次模型数、r=平均额外修复数。举例 N=1,000,000、Tin=8,000、Tout=1,000、a=1、r=0.1，**虚构敏感性价格** pin=$2/pout=$8 每百万 token（不是报价）：全 LLM 每 tool $0.0264、合计 $26,400；f=0.05 为 $1,320；纯代码在线仿真模型费为 0，但有 CPU/blob/索引/开发费。文件处理、容器和真实推理计算另计，不能混进 token 费用隐藏。

假设每模型调用 3 s，100 tool/s 全 LLM 约 330 个在途模型请求、880,000 input token/s；5% 混合约 16.5 个在途。均为规划值，不是测量；长卡片/检索页使上下文变长时应报告 p50/p95 token、修复率/废弃率和每条独立验收通过轨迹成本。模型/上下文价格翻倍会近似翻倍相应成本，成功率不足还增加重跑成本。

降本与复现 D：预生成内容并跨合法任务复用，训练/测试语料隔离；ACL/文件/metadata/分页确定性快速路径；缓存键含 profile、principal+ACL version、query、index/ref/commit、虚拟时间、model/prompt version；只缓存已提交响应。记录模型版本、原始检索态/blob hash、prompt、proposal、validator/修复结果、提交 diff 和最终响应 hash，回放读记录不再采样。固定温度不保证可复现。成熟长尾能力逐步转代码；不要为吞吐删掉校验。

HF 可做的明确在线 LLM 对照试点 D：冻结 `hf_fs search hf://docs/... QUERY` 的完整工具契约、文档语料与可见候选；比较代码检索、LLM 在候选内重排、确定性快速路径+少量 LLM。用独立 relevance 标注/来源核验、未知查询与恶意文档测试，评测来源幻觉、排序迁移、帮助程度、成本。只能证明语义检索近似的收益，不能证明写事务或执行可由 LLM替代；没有真实检索样例校准前，不宣称排序高保真。

## 8. 合成、验证与分期

生成 D：按 seed 变化 namespace/组织关系、同名跨类型资源、私有/gated、ref 历史与分支、README 长度/缺字段/坏外链、图像/二进制大小、近重复 repo、download 分布、config/split 数量、空/多 shard/nested/null/media 数据、索引延迟、可失败执行与任务量。可解任务由状态约束选出，反向构建也须独立验证存在可行操作图；不使用固定 repo 名、第一条结果或“只有唯一不受限资源”等捷径泄题。至少保留 SDK 与 MCP 等多条合法路径，允许先读已知 URI 再搜索，也允许先发现后读取。
