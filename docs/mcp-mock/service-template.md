# <name> 高保真模拟可行性与设计

> 作者/审查者、实际模型与强度、查阅日期、工作树/安装版本、证据边界。事实 F、设计 D、假设 A、待确认 U 分开。先读 shared.md 与原始需求文件，本文仅分析不实现。

## 1. 范围、版本与入口

M/B/X 三层；配置开关、认证与公网分类；源码/安装/锁文件与实际运行版本差距；当前任务完整成员、初始化与评测/SDK/CLI/HTTP/浏览器路径、可用轨迹（找不到也记录检索范围）。重要事实引用仓库路径行号和固定外部 URL、版本、日期。

## 2. 工具与能力清单

提供足以逐工具核对的清单（工具原始名、说明、输入字段与 required/default/校验、输出类型和元数据、读写执行管理属性、状态依赖、已用任务/未来价值、证据完整程度）。大清单可紧凑表；完整 schema 可引用固定源码具体位置但必须点出关键参数与差异。不要仅引用任务已用子集。动态工具列已核实快照与配置条件；其他能力标 U。资源/提示模板/协议错误需要明确核对。

## 3. 领域状态模型

实体/字段/关系、ID/URL、版本历史、约束生命周期、身份权限、文件附件二进制、异步/执行结果；持久化与派生；各入口的共享状态与路由范围。

## 4. 代表性交互序列

至少 5 条超出当前任务且包含多顺序/多工具/分页批量/错误恢复/跨入口/跨服务的序列，写出状态断言；无法适用的序列说明原因。

## 5. 候选实现与推荐

比较保留 MCP 换后端、有状态 MCP、HTTP、SDK 适配、现成服务、fixture/回放、LLM 主导、混合。可以解释不适用项。逐维比较 I/S/C/T/D/P 与开发/运行/维护成本；首选/备选及边界。现成引擎/模拟器须查官方源码/文档实际覆盖，不用产品名推定兼容。

## 6. 保真缺口与取舍

按能力区分可准确复现、近似、分期、U；列出可能训练出的错误规律与检测措施。SQL/类型/NULL/时间/执行、结构化资源/版本/文件等按服务重点深入。未知与不支持不得伪造成功。

## 7. LLM 仿真可行性

回答适合/不适合的能力；代码/LLM 主导/混合三路线；LLM 决策权限与外部验证；状态检索/大上下文/原子提交/冲突与重试/回放；防止资源幻觉、成功偏差、悄悄修复与答案泄露；独立质量验证；单调用模型次数/token/延迟/费用公式与规划假设（非测量/实价）、相较代码开发和长期成本；可接受的对照试点。

## 8. 合成、验证与分期

按 seed 多样状态、任务可解且多路径、独立结果 oracle、隔离/快照/重置/恢复、指标；契约/边界/组合/多入口/差分/未见结构测试计划；真实写入仅列未来条件。区分已有记录能验证与受控真实环境所需部分。优先级以迁移价值等综合决定，不按 finalpool 最小集。

## 9. 待确认与审查记录

证据缺失、所需核验、主要审查问题/证据/作者处理。审查者不能直接改作者报告；作者修订后交统筹确认。

## 10. 能力矩阵行

用一个 csv fenced block 提供本服务能力族/工具矩阵，统筹聚合；字段必须为以下 11 列，字符串有逗号须正确 CSV 引号。可按能力族聚合，但第 2 节工具清单须完整。不得只给结论一个总分。

```csv
object,tool_or_capability,version,operation_type,state_dependencies,proposed_method,llm_role,fidelity_gap,verification_method,priority,evidence
```
